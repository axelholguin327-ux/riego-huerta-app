Flujo principal: regar una zona

1El encargado presiona Regar en la app y confirma.
2IrrigationController llama a la API REST con su JWT.
3La API valida el rol, registra el EVENTO_RIEGO en MySQL y envía el RPC setIrrigation a ThingsBoard.
4ThingsBoard reenvía el comando al ESP32 por MQTT.
5El ESP32 abre la válvula y la bomba y publica la telemetría.
6La app recibe el nuevo estado por WebSocket y actualiza la pantalla.

Flujo de alarmas

1El Rule Engine detecta suelo < 25 % y crea la alarma.
2Un nodo REST API Call la envía a la API, que la guarda en MySQL.
3La API manda una notificación push (FCM) a la app.

¿Por qué una BD propia además de ThingsBoard?

ThingsBoard guarda la telemetría cruda. MySQL guarda la información de negocio: usuarios y roles, tarjetas RFID, eventos de riego con quién y cuánto se regó, y alarmas reconocidas. Así se pueden hacer consultas e historiales flexibles.
